3–5 人，约 60 分钟，机制为竞拍 + 押注 + 商品投机 + 掷骰 + 工人放置。

### 版权处理

玩法机制本身不受版权保护，可以参考；**原版美术与文案受保护，不得照抄**。
因此本实现：

- 棋盘、船、标记全部由**基础几何体 + Canvas 贴图程序化生成**，不含任何原版图像
- 不使用任何外部美术资源，因此也没有资源许可问题（`agent.md` §8）
- 保留货物名、角色名等**规则性术语**（这些是玩法的一部分，不是美术表达）

## 3. 竞标规则实现对照

每一条都标注规则原文与实现位置。

| 规则原文 | 实现 |
| --- | --- |
| 「起标价最低为１元披索（或是ｐａｓｓ）」 | `MIN_BID = 1`；`minLegalBid()` |
| 「在第一段航程中，最老的玩家开始竞标」 | **简化**：数字版无法得知年龄，改为座位第 1 位。`startVoyage()` |
| 「在接下来的航程中，由前一个回合拥有海港负责人的玩家开始竞标」 | `startVoyage()` 用 `harborMaster` 作为起叫人 |
| 「如果开始竞标的玩家 pass，则改由他左边的玩家开始，以顺时针方向依此类推」 | `nextActiveIndex()` 顺时针跳过已过牌者 |
| 「当一位玩家…pass 后，他不能在往后的过程中重新进入竞标」 | `passed` 数组；`already-passed` 守卫 |
| 「竞标过程在除了其中一位玩家之外的所有玩家 pass 之后结束」 | `applyBiddingAction()` 结束判定 |
| 「他将得标价交给海港的钱箱，成为新的港口负责人」 | `applyIntent()` → `payToBank()` |
| 「如果没有玩家参与竞标，上一段航程的港口负责人仍为这个航程的负责人」 | `status = 'incumbent-holds'`，成交价 0 |
| 「玩家的竞标价不能超过他所能付出的价格」 | `creditLimit()` = 现金 + 未抵押股份 × 12 |
| 「对每一张股份，海港的钱箱借款１２元披索」 | `MORTGAGE_LOAN = 12` |

## 4. 原版规则未定义、由本实现补充的部分

这些**不是**原版规则，是为了让程序能跑完而补的。如果你有官方裁定，请以官方为准并改这里。

| 情形 | 原版规则 | 本实现的处理 |
| --- | --- | --- |
| **第一段航程全员过牌** | 未定义（没有"上一段航程的负责人"可连任） | 起叫者以 **0 元**接任港务长（`status = 'no-bid-default'`） |
| **只剩一人但该人从未出价** | 未明确 | 不结束竞标，轮到该人，他必须出价或过牌；若过牌则进入上一行的情形 |
| **得标者现金不足** | 「他必须贷款」 | 自动抵押股份补足，**优先抵押当前单价最低的**（原版允许玩家自行选择抵押哪一张） |

## 5. 待核对项（重要）

以下数值**没有可靠来源**，是按规则文字推断的占位值，已集中在
`src/config/board-layout.ts` 并标注「待核对」。第一版的三个功能**没有用到**它们，
但后续阶段开始结算前必须核实。

| 项 | 当前占位值 | 影响 |
| --- | --- | --- |
| 黑市价格轨刻度 | `[0, 5, 10, 15, 20, 25, 30]` | 股份价格、游戏结束判定 |
| 港口报酬 A/B/C | `[30, 20, 10]` | 港口小弟的利润 |
| 修船场赔偿 A/B/C | `[15, 10, 5]` | 保险仲赔额 |
| 货仓（ware load）上各格的利润数值 | **未录入** | 船上小弟的利润 |
| 4 颗骰子颜色与 4 种货物的对应关系 | 按 GOODS 顺序推定 | 掷骰推船 |

另外两点需要确认：

1. **货仓利润的分摊方式**：规则写「每个货仓上有可分配的利润，由同伙均分」，
   但「选择该货仓中最低价的空的空格」里的"价"指的是**放置费**还是**利润额**，中文规则表述有歧义。
   实物棋盘上每格印的是哪一种，需要看图确认。
2. **「最老的玩家开始竞标」在数字版如何处理**（随机？房主？固定座位？）。

## 6. 架构与文件对应

严格按 `agent.md` §3 分层，依赖方向单向 `ui → render → core`。

```
src/
├── config/           规则常量与棋盘拓扑（纯数据）
│   ├── constants.ts      起始资金、起拍价、抵押额、人数与小弟数…
│   └── board-layout.ts   航道/港口/修船场/货物/价格轨 + 待核对占位值
├── core/             纯规则，零 three.js 依赖
│   ├── types.ts          Player / ShareCard / netWorth
│   ├── rng.ts            带种子的 PRNG（mulberry32）+ Fisher-Yates
│   ├── bidding.ts        竞标状态机（纯函数、不可变）
│   └── game.ts           GameState + applyIntent（唯一状态推进入口）
├── render/           Three.js
│   ├── coords.ts         棋盘坐标 → 世界坐标的唯一换算点（纯数字）
│   ├── palette.ts        配色与共享材质
│   ├── textures.ts       航道长条 / 价格轨的 Canvas 烘焙
│   ├── labels.ts         中文文字贴图（带缓存与 dispose）
│   ├── boat.ts           平底船程序化模型
│   ├── board.ts          棋盘装配
│   ├── scene.ts          渲染器/相机/光照/循环 + 自动取景
│   └── dev-hook.ts       仅开发环境：取景检测
└── ui/               DOM 界面
    ├── start-screen.ts   人数与玩家名
    ├── bidding-panel.ts  竞标面板
    └── hud.ts            帧率 / draw call / 三角形 / 随机种子
```

### 联机预留

用户已确认「本地热座为主，架构预留联机接口」。落地的三个约束：

1. **状态推进只有 `applyIntent(state, intent)` 一个入口**，`Intent` 是纯数据、可序列化
2. 状态**不可变**，每次走子产生新快照（便于回放与同步）
3. 洗牌走**带种子的 PRNG**，种子由 HUD 显示并写进对局记录

将来加联机时，对端只需传输 `Intent`，规则层不需要改动。

## 7. 验证

### 单元测试（`npm test`）

33 项，覆盖竞标的全部分支与不可变性：

| 分组 | 覆盖 |
| --- | --- |
| 基本轮转 | 起叫者优先、必须高于最高价、必须整数、非本人回合被拒、起叫者过牌后左邻接手 |
| 过牌者退出 | 过牌后不再获得行动权、已过牌者不能重新进场 |
| 结束条件 | 除一人外全过牌得标、只有一人出价得标、无人出价在任者连任、无人出价无在任者接任、仅剩一人未出价时不结束、结束后拒绝动作 |
| 信用额度 | 额度公式、已抵押股份不计入、超额被拒、恰好等于额度被接受 |
| 建局 | 人数与小弟数、人数越界抛错、种子可复现、初始阶段 |
| 结算 | 扣款、港务长就位、结束后拒绝意图、现金不足自动抵押、日志内容 |
| 不可变性 | `applyIntent` 不修改传入的 state 与 players |

### 浏览器端到端（Playwright，headless Chromium）

实测走通：开始界面选 3 人 → 进入棋盘 → 玩家1 出价 5 → 玩家2 出价 8 → 玩家3 过牌 →
**轮到玩家1（过牌者被正确跳过）** → 玩家1 过牌 → 玩家2 以 8 元得标、余款 22 元 →
出价按钮禁用。**控制台无报错、无 pageerror。**

### 性能实测（`agent.md` §6 预算）

| 指标 | 实测 | 预算 | 结论 |
| --- | --- | --- | --- |
| draw call | 82 | < 150 | 通过 |
| 三角形 | 1,912 | < 300,000 | 通过 |
| 产物体积 | 590 kB（gzip 151 kB） | — | 主要是 three.js 本身 |

帧率在 headless SwiftShader 软件渲染下为 24–33 fps，**不代表真实 GPU 表现**，
未在本机显卡上实测，标记为**未验证**。

## 8. 已知取舍

1. **棋盘布局是自定的**，不是原版棋盘的复刻。原版的具体印刷排布需要看图才能还原。
2. **没有实现行动牌**（原版有 20 张牌），v1 未纳入。
3. **小弟只有数量，没有放置实现**（属于第二阶段）。
4. **相机只能旋转与缩放，不能平移**（`enablePan = false`），避免玩家把棋盘拖出视野。
